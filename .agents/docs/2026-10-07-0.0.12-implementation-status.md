# Joint 0.0.12 implementation status

Scope: all W1–W8 and G0–G4 of the approved joint release plan. No merge or
publication. Product base: a0cd29b (0.0.11); engine candidate remains experimental.

## Current evidence

- Engine draft: https://github.com/Sunrisepeak/mcppls-clangd/pull/2
- Tracking issue: https://github.com/Sunrisepeak/mcpp-language-server/issues/45
- G0 implementation rejects release packaging with nonsteady patches or
  nonexistent executable tests. Current seven patches correctly fail release
  eligibility; this is not a candidate ready for release.
- Crash corpus replay executes asserted LSP sequences and records binary SHA,
  clean exit/crash/timeout/error outcomes. Empty corpus fails. Debugger absence
  now fails the Windows evidence job. Symbol/PDB identity is still unverified.
- A/B product completion requires module symbols, probe subprocess failure
  fails evidence, and missing latency metrics cannot vacuously pass.
- Fast Linux negative controls: 3 test groups passed, including wrong semantic
  response, crash and timeout. These prove gate behavior only.

## Outstanding work

G0 is incomplete: isolate 0002/0006 and C7; collect raw hangs and nonempty real
crash inputs. G1–G4 remain open, including semantic/root-cause repairs,
optimization budgets, formatting/extensions, immutable identity/kit wiring,
four-platform packages and installation, real project/provider verification,
qualifying nightly history and RC soak. Existing historical measurements are
reference evidence, not acceptance of new candidate bytes.

Keep routine testing below one third of implementation effort. Use focused
reproductions to decide fixes, then one combined verification per stable batch.

## Implementation batch 2

- Product draft: https://github.com/Sunrisepeak/mcpp-language-server/pull/46
- Version tool advanced the product and editor versions to 0.0.12. Local Linux
  dev build passed both on the 0.0.11 base and after that version update.
- Engine 0008 isolates index-only completion behind an explicit experimental
  flag. Member/prefix/pointer assertions pass with the semantic default; the
  original experimental bytes fail all three. This is correctness containment,
  not proof of the W1 performance target.
- Engine 0009 stores native nanosecond timestamps and file identity rather than
  second-truncated mtime. Synchronous same-size/same-second exported-member
  replacement passes. Asynchronous replay still exposes a generation/preamble
  race, also seen with vanilla; it remains blocking and is selectable with
  `completion_quality.py --async-scheduling`.
- Patched LLVM caches now include series/overlay content and apply.sh rejects a
  stale marker instead of silently skipping a changed series.
- Local carried range/tidy lit: 2 passed. Semantic LSP smoke completion, hover,
  current-version diagnostics and symbol-checked latency passed. Tiny-project
  timings are not real-project performance acceptance.
- Product inferred fixture against the semantic-default engine before 0009:
  C7 failed after 181.8 seconds, other checks passed (186.1 seconds total).
  Log: `/tmp/joint-inferred-semantic.log`. This disproves that disabling 0006
  alone fixes C7. Debugger attach was unavailable under the current ptrace
  policy; no machine security policy was changed.
- Engine PR CI discovered 0007 omitted WindowsCrashDumps.h from its patch;
  0010 now carries the header. Prior local builds had an untracked copy and
  therefore did not prove clean buildability. New CI is required to verify it.
