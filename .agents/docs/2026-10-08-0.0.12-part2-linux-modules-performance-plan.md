## 3. 根因证据与分析边界

### 3.1 已证实的延迟缺口

最终 joint67 的 `std-qualified` 在 3 次启动、每次 30 轮中，186 个语义请求全部通过：

| 阶段 | 样本 | p50 | p95 | 判定 |
|---|---:|---:|---:|---|
| cold-open | 3 | 2099.93ms | 3694.20ms | 单列冷启动，不混入 warm 门槛 |
| settled-warm | 93 | 169.43ms | 180.68ms | 通过 200ms |
| edited | 90 | 247.03ms | 257.89ms | 未通过 200ms |

数据位于引擎 `tests/evidence/joint66-67/std-3x30.json`。从 257.89ms 到 200ms 至少需要约 22.4% 的 p95 改善；建议实现争取 160–180ms 的余量，但不把建议余量替换成新的硬门槛。

### 3.2 已有 trace 的归因

私有 trace-only 单轮中，edited 请求约 247.29ms，模块验证 82.95ms：canonical scanner lifetime 69.02ms（其中 getP1689 68.93ms），manifest admission 13.69ms。没有 publication wait；BMI freshness 两个稳定 generation 均命中。warm manifest lookup/replay 约 10.58–10.91ms。

标准库 completion 的 Sema 约 134–152ms，候选 populate 约 20–23ms、merge 约 12–13ms；JSON Sema 约 13–17ms。不能把嵌套 span 相加当总耗时，不能将返回候选数解释为遍历的声明总量。69ms 是本次扫描耗时，不是已证明可全部消除的收益。

现有证据优先指向：正文编辑触发完整 canonical 重扫、manifest 反复读入验证，以及标准库 Sema/候选处理成本。未证实等待锁、BMI 重建或产品缓存是这轮主要瓶颈；需由新的匹配 profile 验证，不提前指定唯一根因。

### 3.3 已排除的捷径

切换 DependencyDirectivesScan 的候选在现有磁盘/dirty-header `#error` 控制中失败，且 child FS 观察不完整，已拒绝。不得复活不完整 lexical import 指纹、忽略错误、关闭 PCH/BMI 校验或 index-only 任意候选路径。

### L2：按收益实施小步优化

以下是优先分析的路线，不承诺所有路线都应实现。每次只加入一个可审阅生产变化，保留 baseline/candidate/消融结果；无收益或破坏正确性的候选撤回。

**A. 消除请求内重复扫描与验证。** 使用显式不可变的当前请求证明，绑定完整 draft、command、CDB generation、环境和完整观察输入。模块 names/textual 判定消费同一证明，避免一个请求得到 names 后又按原 full-main key 再扫一次。消费前验证证明适用性；不得跨编辑复用未验证的旧 token。保留原 key 的并发 publication 协调、取消和错误语义。

**B. PCH 辅助 canonical 全文扫描。** 已有 5 项前置测试通过，但生产路径尚未实现；收益需测量。只有当前 prefix 完全一致、原 canonical-prefix manifest 与实际 compiler manifest 都能独立重放、原 PCH 经 audit 不导入模块时才借用。实际 canonical scanner 仍读取当前完整正文至 EOF，判定 module role/imports，保留宏回调和真实错误。

- `PreambleData` 继续拥有已有 PCH；借用已计费的 immutable prefix cache entry，另为 compiler evidence 在同一个 32MiB/256 项总预算中预留容量。借用在 eviction 后仍计费，预算拒绝则回退；不能新增第二个未计费池。
- 在 scanner 创建前准备拥有明确生命周期的 CI、完整当前 main、VFS；早期 hook 仅传必要 PCH/main 字段，保留原宏/UsePredefines/其他扫描选项，仅对齐已验证 Compatible 系统注释设置。
- `DisablePCHOrModuleValidation=None`；不能开启 configuration mismatch 逃生通道。保留实际 compiler/PCH/BMI 内容与配置验证。
- 独立验证 canonical prefix 的 driver/toolchain 观察和 compiler 观察。完整内容、负查询、原拼写、native alias partition 都参与证明；不能任意删除“主文件事实”。
- 辅助 scan 生成 request-local proof；虚拟 PCH 路径/观察不进入普通 raw-FS memo。旧 PCH 只在调用方已有所有权覆盖的同步生命周期内借用。
- prefix/header/CDB/env 变化、提供模块、证据过期/不完整、预算拒绝、PCH 不兼容/缺失/损坏等回退原 canonical 一次。取消立即退出，不把取消变成重试。
- 验证完成前不导出 0068。若公共布局变化，重建全部受影响消费者后才能运行集成二进制。

**C. 降低 manifest 验证成本。** 依据 L1 定位同一验证事务内的重复 open/read/hash/alias 检查和分配；使用被证明有效的同一快照，减少重复工作。不能仅凭 size+mtime 或保存计数跨事务认为输入未变；same-size/same-mtime、dirty overlay、负查询转正、CWD/路径别名必须仍能使结果失效。不得在 registry mutex 内执行文件 I/O。收益同时报告 CPU、读字节与持有内存，避免以常驻副本换隐藏的无界增长。

**D. Sema 与候选处理。** 在 trace/profile 证明成本后，检查 empty-index 情况下无效匹配/USR 生成、重复遍历、排序/merge 和分配，评审能否将廉价且语义等价的筛选提前。USR/linkage 计算可能有缓存副作用，不能未经控制就改变顺序。保留重载、模板、成员/继承/可见性、snippet/resolve 和真实 Sema 来源；不跨 ASTContext 缓存裸 Decl 指针，不以截断合法候选换速度。更大的 BMI/AST summary 或序列化设计只有简单路径不足且证据充分时另出设计供 review。

**E. 冷加载与大 DAG。** 在编辑延迟收敛后分析 provider 表、单飞构建、transitive generation、BMI 校验/复制、worker 调度和失败传播；保留已实现预算、lease 和 worker 限制。先证明队列/依赖瓶颈，再改并行度；不直接加线程、放大栈或提高超时。

交付：每个修复对应根因、编号 patch、台账 evidence/scope/drop 条件及本地结果。上游缺陷新增归因/补偿前按 contributing skill 核对 #24；产品驱动错误在产品修复，不冒充上游问题。

### L3：本地 Linux 收敛与产品闭环

集成候选通过以下层级后才进入其他平台：

1. 小步回归：选定现有单测与 raw 反例，覆盖内容/宏/import/role、脏缓冲、负查询、CDB/env、PCH 缺失/不兼容、alias、取消/关闭、预算拒绝和并发 publication。
2. 探索性 Qt std/JSON 对照：真实 Sema 与实际 GCC 插入通过后才看速度；单轮只用于筛选，不当统计验收。
3. 最终 Linux 分布：12 个既有语境分别至少 3 次独立启动、每启动 30 轮；cold/warm/edited 分开。计入错误/超时/缺候选，保留全部样本、nearest-rank p95 和缺失计数；编译选定插入并补足关键重载/snippet/resolve 边界，说明覆盖范围。
4. 同一产品二进制只替换引擎的对照，再以最终同源 payload 跑真实 VS Code、inferred/C7、typing/import/autosave、UP20。raw 与产品缓存延迟分开，不以产品答案缓存证明 raw 改善。
5. Linux 干净构建和导出 series 字节一致性验证；发布身份记录实际 built checkout，PR head 与 merge SHA 分列，资源文件也校验。完成候选阶段资源与恢复验证。

开发期间先用短控制和少量样本；只在实现稳定且有收益时运行一次完整分布。必要验证不省略，已通过检查不反复重跑。测试投入遵守此前用户要求：不超过实现时间的三分之一；若必要完整验收超预算，报告时间并调整批次/范围供 review，不降低门槛或称未执行为通过。

### L4：扩展到其余支持平台

Linux L3 通过后，用同一 LLVM pin、series digest、构建配方生成 Windows 和 ARM macOS 原生候选；不复制 Linux 对象或假定 ABI/文件系统相同。

- Windows：先解决有界采集后的 `module-faults` 原生失败；验证文件身份/共享模式、rename/delete、lease/锁、取消；UP12 最终同源 PDB/corpus 重放，UP13 缺失的真实输入继续补齐，不伪造 crash proof。

- 两平台分别记录本机 baseline/candidate、raw/产品、CPU/RSS/物理缓存、冷/温分布。CI 用于原生/可移植性与回归确认，不用调大门槛让慢机器掩盖问题；平台差异有证据后交用户 review。
