## 3. 根因证据与分析边界

### 3.1 已证实的延迟缺口

最终 joint67 的 `std-qualified` 在 3 次启动、每次 30 轮中，186 个语义请求全部通过：

| 阶段 | 样本 | p50 | p95 | 判定 |
|---|---:|---:|---:|---|
| cold-open | 3 | 2099.93ms | 3694.20ms | 单列冷启动，不混入 warm 门槛 |
| settled-warm | 93 | 169.43ms | 180.68ms | 通过 200ms |
| edited | 90 | 247.03ms | 257.89ms | 未通过 200ms |

数据位于引擎 `tests/evidence/joint66-67/std-3x30.json`。从 257.89ms 到 200ms 至少需要约 22.4% 的 p95 改善；建议实现争取 160–180ms 的余量，但不把建议余量替换成新的硬门槛。

### 3.2 已有 trace 的归因

私有 trace-only 单轮中，edited 请求约 247.29ms，模块验证 82.95ms：canonical scanner lifetime 69.02ms（其中 getP1689 68.93ms），manifest admission 13.69ms。没有 publication wait；BMI freshness 两个稳定 generation 均命中。warm manifest lookup/replay 约 10.58–10.91ms。

标准库 completion 的 Sema 约 134–152ms，候选 populate 约 20–23ms、merge 约 12–13ms；JSON Sema 约 13–17ms。不能把嵌套 span 相加当总耗时，不能将返回候选数解释为遍历的声明总量。69ms 是本次扫描耗时，不是已证明可全部消除的收益。

现有证据优先指向：正文编辑触发完整 canonical 重扫、manifest 反复读入验证，以及标准库 Sema/候选处理成本。未证实等待锁、BMI 重建或产品缓存是这轮主要瓶颈；需由新的匹配 profile 验证，不提前指定唯一根因。

### 3.3 新增本地 profile 与候选边界

- **Manifest：**一次主重放观察到 622 个不同文件，每个路径因 Open/FileStat/Read 各开关一次，共读约 9.22MB；1710 次 stat 中 1053 次失败。代表性冷启动后 lookup 中位 wall 13.68ms，插桩计量的底层文件操作约 7.64ms。额外 shadow BLAKE3 约 2.17ms 只是分析开销，不是原实现 hash 的 exclusive 时间；目录迭代未完整计时，不能将剩余时间全归为 hash。
- **Sema merge：**`std::ve` 的 6975 个语义候选最终返回 65 个；原路径即使 index slab 为空仍逐个生成 USR，单轮约 6.88–7.34ms。私有 empty-index 跳过候选已通过 136 项现有 CompletionTest 与 4 次真实语义/GCC 插入控制，但探索性 edited 仍约 261ms，未证明匹配 A/B 收益，不进入正式 series。
- **PCH 集成：**已验证借用 prefix entry 在 eviction 后仍计费、当前完整正文可选择新的导入，以及 same-size/same-mtime header 改动使旧证明和新辅助尝试失效。仅 2 项初步集成控制，不代表宏状态、异常、取消、并发或性能通过。
- **Linux canary：**最终 67 补丁允许正文新增 import 时保留经完整审计的 import-free PCH，不能以“不收缩”直接判错。修订的 canary 同时要求真实 typed Sema、正文保留的审计证明，以及 header 新增 import 后收缩；本地 fallback 与合法保留两条对照通过，最新原生 CI 仍需核对。

这些新 profile 带插桩开销，且开发构建期间机器负载不同；只支持成本定位，不替代 3×30 的正式分布或最终版本结论。

### 3.4 已排除的捷径

切换 DependencyDirectivesScan 的候选在现有磁盘/dirty-header `#error` 控制中失败，且 child FS 观察不完整，已拒绝。不得复活不完整 lexical import 指纹、忽略错误、关闭 PCH/BMI 校验或 index-only 任意候选路径。

### 3.5 以全头文件项目为直接参照，集中优化差额

按用户最新指示，首要性能参照是同一 Qt 项目的全头文件版本。固定源代码语义、补全位置、编译器/SDK、宏、优化参数和后台索引设置；仅改变依赖表达方式为 include 或 import，并记录不可避免的参数差异。由同一 mcppls-clangd 基线与候选分别跑两种输入，形成“全头文件/Modules × 基线/候选”四格对照，避免把不同引擎本身的差异误归因于 Modules。stock 对照仍保留，不能代替这个直接参照。

优先比较稳定后的正文编辑：等待/调度、扫描与输入验证、PCH/BMI 加载、Sema、候选处理、总响应。首次构建 BMI 与稳定请求分别报告。全头文件与 Modules 不要求内部执行相同，但相同有效补全的响应速度应尽量对齐；同时保留现有 200ms 绝对门槛。记录 Modules 相对全头文件的绝对差额和比例，而不是只报告达标。四格匹配分布已完成：每臂 3×30，edited p95 的全头文件 baseline/candidate 为 184.52/155.90ms，Modules 为 255.22/188.61ms。候选仍差 32.71ms（约 20.98%），继续按剩余差额定位，不宣称完全对齐。完整证据见 [实施状态](2026-10-09-0.0.12-part2-implementation-status.md)。

当前可用于排序的证据是：最终 67 基线单轮 edited 约 239–244ms；PCH 辅助扫描的短实验将 canonical 扫描降至约 32ms，但合并验证事务后 edited 仍约 323ms。该候选每次完整证明会读约 33.64MB PCH 和约 9.22MB其他输入，prefix/compiler/full 证明仍执行三组。上述数字来自短实验，不是正式 p95，也不是全头文件/Modules 的匹配差额；它们说明当前辅助路线的验证成本抵消了扫描收益，不能作为生产性能修复提交。

按分段差额选择最大增量，而不是固定优先扫描：本轮对照已经证明两侧 Sema 成本不同，因此首先优化导入声明的加载。扫描/验证作为后续路线，只有新的净收益证据才提高优先级。每个候选用一次短匹配对照筛选，无收益便停止扩大测试；不同时展开多条缺乏差额证据的优化路线。共享观察必须有当前输入一致性的证明，不能以路径或 size+mtime 命中跳过内容变化。

**首轮直接对照已完成：**同一最终 67 二进制、原源文件 URI/CDB/编译参数，使用未保存草稿切换 include/import；两侧各 1 次启动、1 轮正文编辑、4 次 completion，全部真实 Sema 与 GCC 选定插入通过。全头文件 warm 72.89/74.91ms、edited 177.18ms；Modules warm 175.05/178.57ms、edited 248.21ms。稳定语义执行分别约 52.80–56.29ms 与 132.35–135.71ms；edited 模块扫描/验证分别约 115.09ms 与 83.12ms。这一短、带 trace 的实验尚非正式分布，但已改变优化排序：优先调查 Modules 语义声明加载/候选遍历的约 80ms 增量，而不是假定两侧 Sema 成本相同。具体证据在引擎 `tests/evidence/part2-linux/textual-module-pair/`。

全头文件依赖须放在 Qt 之前以避免 `emit` 宏污染 `<syncstream>`；记录其额外宏/声明暴露，不能宣称全部 API 等价。复制到新路径的 Modules 对照曾使 PCH 输入重放失败、语义执行升至约 960ms，已排除；新增 `--draft-source` 探针保持原 URI、原磁盘源和实际插入编译上下文，避免该测量偏差。

### 3.6 已定位的主瓶颈与本轮优化决定

`DeclContext::lookups()` 会触发外部 namespace 的完整可见声明加载，而 clangd 模糊筛选发生在加载之后。Modules 的 `std` 表每次取约 17,192 个声明 ID，`GetDecl` 约 93–108ms；表枚举与其余工作约 4–5ms。因而本轮重点是减少不可能匹配名称的声明反序列化，而不是加速最终返回的 65 个候选排序。

生产候选采用补全专用接口，直接使用 clangd 现有 FuzzyMatcher；在外部名称表上先筛名称，再对保留名称加载全部声明。普通 lookup 和空补全词保持完整路径，非 identifier、using/inline namespace、重载与模板保持原语义；部分加载不能清除 external storage 标志。谓词绑定精确 source/context、同步作用域且仅消费一次；不改 BMI 格式、不缓存答案、不关闭 PCH/BMI 校验。详见 [接口设计](2026-10-09-part2-filtered-visible-lookup-design.md)。

已有无新增诊断插桩的 Modules 短 A/B/A（每臂 1 启动×5 轮）：edited p95 从前后基线 247.26/252.40ms 降到 187.05ms，全部 36 次选定 GCC 插入通过；每次 65 个返回项的关键字段与实际编辑元组一致。候选 `std-qualified` 的独立 3×30 分布共 186 次真实 Sema 与实际 GCC 插入通过，warm/edited p95 为 117.54/192.28ms；edited 最大 204.59ms，1/90 超过 200ms。前者是短匹配收益证据，后者证明本地该语境的 p95 达标；不能把全头文件单轮 177ms 与候选 p95 192ms 当作严格对齐结论。

四格分布和选定声明加载边界已通过，0068 已导出至本地，68/68 台账检查通过；固定源全系列应用、11 修改文件字节核对与 configure 通过，完整构建与选定消费者运行通过（本地运行库配置见实施记录）。下一批交付为：完成分发身份与运行库资格；补齐剩余模块可见性、snippet/既有 resolve 契约与正确 stock 对照；分解剩余 32.71ms 差额和资源成本；以最终构建做产品闭环及三平台验证。扫描/PCH 实验与主候选分离，性能负例保留，当前不纳入正式优化补丁。

### 3.7 剩余差额：优先减少无关模板推导指引加载

直接对照的目的就是把优化集中到 Modules 额外付出的工作；当前绝对门槛已在开发候选通过，但与头文件版本对齐仍是优化目标。四格对照中的 p95 差额用于衡量结果；定位原因使用逐请求 span、声明数和 CPU，不能把两个分布的 p95 相减当作某一函数的耗时。

| 名称类别 | 每次加载的声明 ID | `GetDecl` 线程 CPU 范围 |
|---|---:|---:|
| 普通 identifier | 13 | 0.165–0.188ms |
| operator | 1,887 | 18.36–22.09ms |
| 模板推导指引 | 1,425 | 28.07–33.25ms |
| literal operator | 99 | 0.658–0.771ms |

原记录、源和构建配方已归档至引擎 `tests/evidence/part2-linux/selected-decl-profile/`。这是带插桩且与干净构建重叠的成本定位；不用于延迟验收，也不预报能节省全部 28–33ms。线程 CPU、请求 wall 和 p95 差额不是同一指标。

**下一项最小候选：**推导指引的名称键携带所属模板的 identifier，复用当前名称谓词，仅加载匹配模板的全部指引。普通 lookup、空补全词保持原路径，部分加载保留 external storage；之后普通 CTAD 仍须能找到此前未加载的指引。不改 BMI 格式或公共接口，operator/literal/using 暂时保留原策略。

执行顺序：先验证未加载名称及后续普通推导指引查找，再验证模板/alias/snippet 返回与原路径一致；通过后做短匹配 A/B/A 和真实插入编译。只有净收益稳定、合法结果不丢失才导出下一补丁。operator 随后根据实际显示名称与 FuzzyMatcher 契约分析；不能直接按普通 identifier 判断或全部跳过。剩余扫描、manifest、候选 merge 再按更新后的 exclusive 成本排序。

## 4. Linux 实施顺序与每阶段交付

### L0：固化可复跑基线，先消除 Linux 回归

- 在 scanner 创建前准备拥有明确生命周期的 CI、完整当前 main、VFS；早期 hook 仅传必要 PCH/main 字段，保留原宏/UsePredefines/其他扫描选项，仅对齐已验证 Compatible 系统注释设置。

**C. 降低 manifest 验证成本。** 依据 L1 定位同一验证事务内的重复 open/read/hash/alias 检查和分配；使用被证明有效的同一快照，减少重复工作。不能仅凭 size+mtime 或保存计数跨事务认为输入未变；same-size/same-mtime、dirty overlay、负查询转正、CWD/路径别名必须仍能使结果失效。不得在 registry mutex 内执行文件 I/O。收益同时报告 CPU、读字节与持有内存，避免以常驻副本换隐藏的无界增长。

**E. 冷加载与大 DAG。** 在编辑延迟收敛后分析 provider 表、单飞构建、transitive generation、BMI 校验/复制、worker 调度和失败传播；保留已实现预算、lease 和 worker 限制。先证明队列/依赖瓶颈，再改并行度；不直接加线程、放大栈或提高超时。
